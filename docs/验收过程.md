# 验收过程指南

本指南用于验证最新交付的自动化能力及相关配置。建议按照顺序完成，每个部分均包含前置参数与验收步骤。

## 1. 通知系统（邮件本地化 + Edge Scheduler）

- **前置参数**
  - Supabase 项目：`SUPABASE_URL`、`SUPABASE_SERVICE_ROLE_KEY`
  - SMTP：`NOTIFY_SMTP_HOST`、`NOTIFY_SMTP_PORT`、`NOTIFY_SMTP_USER`、`NOTIFY_SMTP_PASS`、`NOTIFY_FROM_EMAIL`
  - 任务门户链接：`TASK_PORTAL_URL`（用于构建邮件跳转链接）
  - （可选）默认语言：`TASK_NOTIFY_LOCALE`，当前支持 `zh-CN / en-US`

- **验收步骤**
  1. 运行 `pnpm --filter web lint`，确保代码通过静态检查。
  2. 在 Supabase 仪表盘或 CLI 中执行 `supabase deploy --linked`（或等效流程），部署 `task-notifier` 函数。
  3. 检查 `supabase/config.toml` 中的 `scheduler.jobs` 是否包含 `task-notifier-dispatch` 与 `task-reminder-queue`，并在 Supabase 项目设置中同步 Scheduler。
  4. 新建或更新任务（或执行 `supabase functions invoke task-notifier --body '{"event_type":"assignment_created","assignment_id":"<id>"}'`），确认邮件标题、正文与推送文案已根据事件类型及语言自动切换。

## 2. 推送通知（Expo + FCM）

- **前置参数**
  - Expo：`EXPO_ACCESS_TOKEN`、移动端 `.env` 中的 `EXPO_PUBLIC_SUPABASE_URL`、`EXPO_PUBLIC_SUPABASE_ANON_KEY`
  - FCM：`FCM_SERVER_KEY`（放置在 Supabase Edge Function 环境变量中）

- **验收步骤**
  1. 运行 `pnpm --filter mobile lint` 确保 TypeScript 校验通过。
  2. 在真机或模拟器启动移动端应用，登录后检查 `user_device_tokens` 表应出现两条记录：`provider=expo` 与 `provider=fcm/apns`。
  3. 通过 Supabase SQL 控制台触发 `task_notification_queue` 事件，确认 Expo Push 与 FCM 推送（Android）均能收到通知。若 FCM credential 未配置，函数日志会给出友好提示。

## 3. 指标看板与 Playground

- **前置参数**
  - Web `.env.local` 中已有 Supabase 公共配置。

- **验收步骤**
  1. 启动 Web 开发服务器：`pnpm --filter web dev`。
  2. 打开 `/dashboard/analytics`，检查 Summary Cards 是否展示完成率/验收率/提醒覆盖等新增指标。
  3. 访问 `/dashboard/playground` 查看组件 Playground 页面，验证无需真实数据即可预览仪表板组件效果。

## 4. 附件流程 QA 自动化

- **前置参数**
  - `.env` 中提供 `SUPABASE_URL`、`SUPABASE_SERVICE_ROLE_KEY`
  - 存储桶：`STORAGE_ATTACHMENTS_BUCKET`（默认 `attachments`）

- **验收步骤**
  1. 运行 `pnpm qa:attachments`。
  2. 脚本会依次校验附件桶是否存在、能否生成签名上传链接以及 `task_attachments` 读写权限。当所有步骤输出 ✅ 时表示流程通过。
