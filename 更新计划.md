# 移动端任务清单升级计划

## 目标概述
- 将移动端 App 打造成通用任务/清单工具，支持执行、轻量发布和即时反馈。
- 沿用 Web 端的多语言能力，目前聚焦中英文，保证所有新增界面/文案都可通过现有 i18n 组件切换。
- 兼顾移动办公特性：随时查、随手记、现场拍，Web 端继续承担复杂运营/分析。

## 阶段拆解

### 1. 设计与基础清理
- 统一导航与视觉（Icons、颜色、排版），Tab 改成图标式 Tasks✅ / Publish✍️ / Insights📊。
- 抽象通用任务模型（基础信息 + Checklist + 附件 + 审批流可选），Web/Mobile 共用类型。
- 加强 i18n：新增文案全部进入 `src/i18n/en|zh.json`，复用现有语言切换逻辑。

### 2. 任务体验
- 列表支持多视图 & Filters（状态/时间/标签 Chips），使用图标表达关键信息（⏰ 截止、📎 附件）。
- 详情页增加 Checklist、附件区、时间线，强调图标化交互（✅/⚪、📷、📝）。
- 推送 & App 内提醒整理在统一通知中心，状态变化有 Toast/Badge。

### 3. 轻量发布
- 参考 Web Composer，在移动端实现任务发布：标题、描述、截止、Checklist、接收人、附件要求、提醒。
- 提供模板（课程任务、巡检、会议纪要等）与「一键分享」(深链/二维码)。
- Insights 页输出我发布任务的完成率、逾期 Top、提醒统计。

### 4. 离线与上传增强
- 将任务/Checklist 状态与附件上传接入本地缓存（AsyncStorage/SQLite），失败进入 Pending 队列，可视化展示重试按钮。
- 网络状态监控 + 弱网提示，支持草稿箱（未提交任务/反馈）。
- 复用 Web 端的 Dexie 思路，确保两端数据结构一致，便于同步策略共享。

### 5. 质量与工具
- 补齐测试：Vitest 覆盖 `useAssignments`、`useInvites`、`taskStore`、模板逻辑；后续接入 Detox/Maestro 做关键路径 E2E。
- 引入 ESLint/Prettier，CI 检查多语言文件是否齐全（同 key 的 en/zh）。
- 监控指标：任务加载时延、离线成功率、附件重试统计。

## 风险与协作
- 多语言：所有新增字符串先在英文定义，再同步中文，避免 hardcode。
- 发布与执行两端逻辑共用需谨慎，考虑抽出 `@project-ark/tasks` 包沉淀。
- 移动端不打算覆盖全部管理功能，Web 仍负责复杂审批/批量操作，保持定位清晰。
